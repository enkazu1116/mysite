# UUID
## 概要
ID付与を行う場合はUUIDを使用する。
UUIDのバージョンは、v7を使用する。

### v7の採用理由
今までよく使用されていたv4は完全ランダムなため、DBのインデックスによる検索効率を損なうデメリットが存在していた。
v7の場合は、先頭部分が生成時のタイムスタンプになっているため、効率的に検索が行える。
ただ、デメリットとしていつ作成されたのかが特定されてしまう側面を持つ。
しかし生成時間が特定されることがセキュリティ上の懸念となることはないため、採用とする。

### なぜUUIDなのか？
今回作成するサイトは小規模ではあるが、分散環境の構築やDBのシャーディングなど将来的に試したいことを行う際に
対応が容易に行えるようUUIDを使用する。

**なぜ連番IDではダメなのか？**
複数サービスが並行してIDを生成する場合に、IDが衝突するリスクがある。
今回の場合は、衝突回避が主な理由として考えている。
